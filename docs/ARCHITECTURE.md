# 系统架构

## 设计目标

本项目的目标不是在玩家推进对白时实时调用 TTS，而是预先完成全部可枚举对白的
合成，让游戏运行时只承担事件捕获、规范化、查表和播放。

设计约束：

1. 不使用 OCR，不依赖屏幕分辨率和字体；
2. 不修改游戏 `.pak`；
3. 玩家端不加载 TTS 模型；
4. 新对白必须立即打断上一句；
5. 生成过程可断点续跑，并可按角色或 job ID 增量修复；
6. 角色画像必须区分“游戏证据”“LLM 推断”和“人工复核”。

## 两条相互解耦的链路

### 离线构建链路

```text
游戏本地化资源
  → 对白与角色目录
  → 官方元数据（可选）
  → LLM 角色画像（可选）
  → 证据冲突消解与声线分组
  → VoiceDesign 锚点
  → Base 模型 ICL 克隆批量生成
  → 音频完整性检查
  → compact runtime lookup
```

`catalog/` 负责建立结构化目录，`bridge/` 负责模型推理，`scripts/` 负责检查和
发布。生成产物使用内容哈希命名，因此重复运行不会因为遍历顺序改变文件名。

### 游戏运行时链路

```text
游戏 UMG 对话控件
  → UE4SS Lua 事件桥
  → dialogue_events.jsonl
  → PowerShell/Python 播放器
  → 规范化 + SHA-256
  → runtime_lookup.compact.json
  → WAV
```

Lua 桥只监听已确认的对话组件和文本字段：普通对话、对话模块旁白、全屏滚动
旁白等。桥接层不运行模型，也不解析声音资源。

## 角色画像和声线分组

角色画像的证据优先级为：

1. 游戏内官方人物描述；
2. 角色在多个场景中的对白；
3. 资源路径、身份字段和肖像人工复核；
4. 显示名中的弱提示。

缺少证据时应保留 `unknown`，不应只按名字猜性别、年龄或性格。
`catalog/profile_characters.py` 生成结构化候选画像，
`catalog/build_voice_plan.py` 再把确定性游戏证据、LLM 结果与人工复核合并，记录
冲突来源后形成最终 voice group。

泛化 NPC 可以共享声线组；主要人物通常保持独立声线。旁白作为独立角色处理。

## 锚点与对白生成

每个 voice group 包含一段稳定的 `voice_design_prompt` 和锚点文本。优先选择长度
适中、情绪不过激、没有占位符的代表性台词；没有合适台词时使用中性模板。

参考实现采用：

- Qwen3-TTS VoiceDesign 生成锚点；
- Qwen3-TTS Base 使用同一锚点进行 ICL 克隆；
- 动态 batch size 与动态 codec token 上限；
- 触顶检测、拆批、确定性重试和 x-vector 回退；
- 对纯标点台词生成简短叹息、惊疑或惊呼；
- 以已存在 WAV 和进度文件实现断点续跑。

生成脚本中的限制是参考构建在 RTX 5090 上稳定运行后的工程参数，不保证适用于
所有驱动、模型版本和显卡。新硬件环境应先使用 `--limit` 小规模验证。

## 运行时索引

主键材料为：

```text
NFC(normalized_speaker) + "\0" + NFC(normalized_text)
```

对 UTF-8 字节计算 SHA-256。规范化过程统一换行与连续空格，但保留对白语义。

运行时依次尝试：

1. 说话者 + 台词精确键；
2. NFKC 兼容形式的精确键；
3. 只按文本查找的唯一声线兜底键；
4. 少数经过审核的前缀规则。

只有当同一文本在所有候选中指向同一音频时，才可进入 text fallback；否则必须
记录冲突，避免给同一句文本错误套用另一个角色的声音。

## 播放与变速

社区播放器使用 Windows `PlaySound` 异步播放 WAV。出现新事件时先停止当前声音，
再播放新音频。自定义倍速使用轻量级 WSOLA 时间拉伸生成一个临时 WAV，尽量保持
音高；处理失败时回退原速。

## 故障隔离

- 桥接层故障：检查 UE4SS 日志、引擎版本覆盖和事件文件；
- 索引故障：记录 `[MISS]`，不触发在线生成；
- 音频缺失：记录路径但不破坏游戏流程；
- 生成故障：按 job ID 断点续跑，不影响已完成文件；
- 单角色音色问题：只替换该角色 job ID 对应 WAV，无需重打完整包。
