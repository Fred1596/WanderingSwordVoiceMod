# 故障排查

## 一直显示 `Waiting for the game dialogue bridge...`

这表示离线音频播放器已经就绪，但 UE4SS 游戏内事件桥尚未创建对话事件文件。v1.0.1 起播放器不会持续刷屏，而会读取 `UE4SS.log` 并给出具体原因。

1. 完全退出游戏和配音窗口。
2. 重新运行 `1_一键安装Mod.cmd`，安装器会自动配置 UE 4.26。
3. 运行 `4_检查安装.cmd`，确认出现 `[OK] UE4SS engine version override: 4.26`。
4. 再运行 `2_启动配音并启动游戏.cmd`。

若仍失败，请提供游戏目录下的 `Wandering_Sword\Binaries\Win64\ue4ss\UE4SS.log`。日志正常时应包含：

```text
Using engine version: 4.26
PS scan successful
[WSVOICE] native dialogue bridge ready
```

如果看到 `Failed to find EngineVersion` 或 `Fatal Error: PS scan timed out`，说明旧配置仍未修复，请确认运行的是 v1.0.1 安装器，并确认检查窗口显示的游戏路径就是当前实际启动的 Steam 游戏路径。`ConsoleManagerSingleton: found 2 unique values` 在本游戏中可以单独出现，不是本 Mod 的致命错误。

## 安装器找不到游戏

在 Steam 库中右键《逸剑风云决》→“管理”→“浏览本地文件”，复制打开的目录路径。重新运行安装器并粘贴该路径。正确目录中应有 `JH.exe`。

## 安装时提示拒绝访问

关闭游戏和 Steam 对游戏文件的占用，然后右键 `1_一键安装Mod.cmd`，选择“以管理员身份运行”。

## 提示已有其他 dwmapi.dll

安装器检测到未知 DLL，为防止覆盖其他 Mod 加载器会停止。先备份该文件，并确认它是否属于现有 UE4SS。不要直接覆盖来源不明的 DLL。

## 启动游戏后没有 `[PLAY]`

1. 运行 `4_检查安装.cmd`。
2. 确认播放器窗口仍处于 `[READY]` 状态。
3. 确认游戏出现的是正式人物对话框，而不是菜单说明、物品描述或战斗飘字。
4. 查看游戏目录中的 `Wandering_Sword\Binaries\Win64\ue4ss\UE4SS.log`。
5. 确认 `ue4ss\Mods\mods.txt` 包含 `WanderingSwordVoiceProbe : 1`。
6. 确认日志包含 `[WSVOICE] native dialogue bridge ready`；如果没有，优先按上一节修复运行态桥接。

## 有 `[PLAY]` 但听不到声音

1. 检查 Windows 音量合成器中 PowerShell 是否被静音。
2. 检查当前默认播放设备。
3. 双击任意 `data\offline\audio` 下的 WAV，确认系统可以播放。
4. 暂时关闭会独占声卡的音频软件。

## 人物切换后上一句还在播放

播放器设计为新对白出现时立即中断旧音频。如果没有中断，请确认没有同时启动两个发布包；重复启动时正常会提示 `Another voice player is already running.`。

## 游戏启动时崩溃

1. 先运行 Steam“验证游戏文件完整性”。
2. 暂时将游戏启动参数设为 `--disable-ue4ss`，确认是否为 UE4SS 兼容问题。
3. 游戏大版本更新后，等待兼容新版事件桥。
4. 提供 `ue4ss\UE4SS.log`，不要只发“打不开”。

## 被安全软件拦截

UE4SS 通过代理 DLL 注入 Unreal Engine 游戏，部分安全软件可能启发式报警。只从发布者提供的固定页面下载，并核对发布页公布的 SHA-256。无法确认来源时不要添加白名单。

## 文本显示乱码

发布脚本会自动切换控制台到 UTF-8。若仍乱码，请在 Windows“区域”设置中更新系统语言支持，或使用新版 Windows Terminal 运行启动脚本。
